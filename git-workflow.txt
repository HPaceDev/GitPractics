Порядок работы с ветками и Pull Request

1. Переключиться на develop и получить актуальные изменения с GitHub.
2. Создать отдельную рабочую ветку из develop.
3. Изменить файлы и проверить результат через git status и git diff.
4. Добавить нужные файлы в индекс и создать коммит с понятным описанием.
5. Перед PR обновить develop и включить её изменения в рабочую ветку. Устранить конфликты, если они появились.
6. Отправить рабочую ветку на GitHub командой git push.
7. Создать Pull Request из рабочей ветки в develop. Описать изменения и назначить ревьюера.
8. Ревьюер проверяет изменённые строки и оставляет замечания.
9. Исправить замечания новым коммитом и отправить его в ту же рабочую ветку. Открытый PR обновится автоматически.
10. После повторной проверки закрыть обсуждения, выполнить слияние PR и обновить локальную develop.

Пример имени рабочей ветки: features/1_git_workflow.
Заголовок первого PR: 1 feature(docs): порядок работы с ветками.

Команды обновления перед отправкой рабочей ветки
Перед переключением веток изменения должны быть сохранены коммитом.
git switch develop
git pull --ff-only origin develop
git switch features/1_git_workflow
git merge develop
git diff --check
git push -u origin features/1_git_workflow

При конфликте нужно исправить отмеченные участки файлов, выполнить git add
для исправленных файлов и завершить слияние коммитом. Отправлять ветку следует
только после проверки результата.
